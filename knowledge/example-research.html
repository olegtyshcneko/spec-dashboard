Example research entry

Knowledge entries are long-form reference pages: research summaries, prior-art catalogs, architectural decisions that span multiple specs. They use the same chrome as spec pages (header, sections, footer) but don't carry status/priority — they're reference material, not work items. Cross-link from the specs they influence.

What this is

Describe the topic of the entry in 1–2 paragraphs. Knowledge entries are valuable when:

  • Multiple specs draw on the same underlying research / prior art and you don't want to duplicate the analysis in each spec.
  • A decision affects the whole project but isn't a "feature" in the usual sense — licensing, vendor choice, content sourcing, etc.
  • You need a place to keep links, citations, or background reading that would otherwise rot in someone's bookmarks.

Optional: embedded Mermaid diagram

The dashboard supports inline Mermaid diagrams via a CDN-loaded script — handy for source-to-feature maps, dependency graphs, or architecture overviews. Diagrams are progressively enhanced: if the CDN fails or JS is off, the raw source still reads fine.

Optional: a table

For comparisons (licenses, vendors, approaches), the spec-meta block isn't enough — drop in a plain HTML table. The default stylesheet keeps tables readable without needing per-page overrides.
